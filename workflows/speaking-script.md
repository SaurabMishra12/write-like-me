# Presentation and speaking script

Load blog-speaker-profile.yaml and shared profiles. Written transcript craft does not establish the user's vocal delivery.

1. Read the actual slide order and audience brief when supplied. Identify what is visible, what should be pointed to, the one intended understanding, and required timing. Never invent a figure or result.
2. Use short speaking units around a concrete object or question. Introduce notation when the visual makes it necessary. A repeated central phrase may help the audience; do not remove it solely for repetition.
3. Mark a pause or pointing cue only if useful. Keep speech natural and respectful. Preserve the user's clear expressions and all technical qualifications. Avoid an academic paragraph read verbatim or an invented personal anecdote.
4. Lock slide numbers, proper names, equations, metric values and conclusions. Read aloud and check timing as an actual task if audio/time is available; otherwise label timing estimated or untested.
5. Review the script against each visual and run the guardian on revisions. Return page-specific notes when a deck exists, not a generic talk outline.

Acceptance: each speaking unit refers to an actual visual or concept, maintains the claim's scope and can be said without losing the audience.

Example failure test: script says an arrow shows causation while the slide reports correlation. Reject the stronger interpretation.
